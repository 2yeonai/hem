- `tests/test_stage1.py`: 실 PostgreSQL + 가상 주문 데이터 전용 테스트.

## 검증 환경과 증거

Python 3.12, Flask 3.1 계열, psycopg 3 계열, PostgreSQL 17.11의 별도 로컬 DB로 검증.
AI/음성 API 키는 빈 값으로 두었고 접수 회귀 테스트는 봇 반환값을 가상 데이터로 대체했다.
기존 golden_set 및 실제 고객을 포함할 수 있는 기존 테스트는 실행하지 않았다.

- 통합 테스트 결과는 이 문서 마지막의 최종 결과를 참조.
- 별도 Python 프로세스에서 가상 주문 확정 후 PostgreSQL을 실제 종료·재시작하고 새 Python 프로세스로 재조회: PASS.
- 재시작 후 주문 1개, 고객 정보 2개, 배송 1개, 이벤트 2개 보존: PASS.
- `pg_dump -Fc` 백업을 별도 빈 DB에 `pg_restore` 후 주문 상태·이력 조회: PASS.
- 첫 재시작 검증 시 실행 도구별 프로세스 격리로 DB 접속 실패. 같은 실행 세션 내에서 시작→쓰기→정상 종료→재시작→검증으로 수정해 위 결과를 얻었다. 운영 DB 문제는 아니다.

테스트 재현: 별도의 폐기 가능한 PostgreSQL DB를 준비하고, 이 폴더에서 실행한다.

```sh
python -m pip install -r requirements.txt pytest
# TEST_DATABASE_URL은 별도 테스트 DB 연결 주소를 비밀 환경설정으로 제공한다.
python -m pytest -q tests/test_stage1.py
```

각 테스트는 무작위 새 스키마에서 실행하며 그 스키마만 정리한다. 테스트 DB에도 운영 주소를 지정하지 말 것.

`실데이터_diff_로그_002.md`, `HANDOFF.md`에는 실제 통화/문자 사례라고 명시된 내용과 실명이 포함된다.
값 자체는 여기 재기재하지 않았다. 꽃집 폴더의 `local_*.json` 3개에서도 이메일 형태 각 1건을 탐지했다.

이는 비밀정보가 없다는 보장이 아니다. 과거 전체 Git 이력, 다른 프로젝트, 이미지/바이너리는 미점검.

공개 저장소 자체의 노출은 이 작업 브랜치의 로그인 기능으로 해결되지 않는다.
저장소 비공개 전환, 실사례 익명화, 필요한 이력 정리와 노출 키 교체 여부는 소유자 결정 후 별도 진행해야 한다.
기존 실데이터 삭제·수정이나 Git 이력 재작성은 이번에 수행하지 않았다.

## 운영 전 설정 — 아직 실행하지 않음

1. 지속 저장되는 PostgreSQL 서비스와 접근 제한·암호화 연결·자동 백업/복원 정책 결정. 유료 가입은 승인 필요.
2. 서버 비밀 환경설정에 `DATABASE_URL`, 무작위 32자 이상의 `SECRET_KEY` 제공. 코드/문서/채팅에 실제 값을 쓰지 않는다.
3. 운영 HTTPS 사용. `APP_ENV=development`는 로컬 HTTP 전용이며 운영에서는 설정하지 않는다.
4. 운영 승인 후 별도 백업을 확보하고 `flask --app app init-db` 실행. 앱 import나 시작만으로 DB 구조가 변경되지는 않는다.
5. `flask --app app create-user --username <계정명> --role admin` 실행. 비밀번호는 숨김 입력 프롬프트에서 두 번 입력한다(12자 이상).
6. 기존 자료가 있으면 먼저 `python import_legacy.py --pending <비공개 파일 경로> --orders <비공개 파일 경로>`로 검사.
7. 실제 이관은 승인 후에만 같은 명령에 `--execute --owner-approved` 추가. 전체 이관은 단일 트랜잭션이고 같은 내용 재실행은 중복 생성하지 않는다.
8. 운영 DB 계정은 앱 사용에 필요한 테이블 권한만 부여하고, 스키마 변경용 계정과 분리한다. 권한 설정/백업 암호화는 제공자 환경에서 검증해야 한다.
9. 승인 후 배포 및 실제 서비스 재시작·재배포에서 영구 저장을 최종 확인한다. 로컬 검증을 운영 환경 검증으로 간주하지 않는다.

Render 기존 경로 주의: 문서 이력상 한글 Root Directory가 거부됐다. Root Directory는 비우고
Build/Start 명령에서 `cd "1. Projects/클로드 꽃집 ai/webapp"`로 진입하는 기존 방식을 유지한다.
자동 배포 연결 브랜치를 이 작업 브랜치로 바꾸거나 main에 병합하지 않았다.
