## 공개 저장소 정리 제안 — 실행하지 않음

1. 승인 후 우선 저장소 전체를 비공개로 전환하고 연결 앱·협업자 접근을 점검한다. GitHub Settings → General → Danger Zone → Change repository visibility. 기존 공개 포크는 자동 비공개가 되지 않는다.
2. 외부 공개가 필요 없는 실사례/첨부자료를 비공개 보관하고, 개발 테스트는 가상 데이터로 교체한다. 노출된 비밀키가 발견되면 해당 키부터 폐기·재발급한다.
3. 이력 정리 전 모든 작업 브랜치/미병합 PR을 보존하고 변경 중단 시점을 정한다. 이번 PR은 미병합 상태 그대로 유지한다.
4. 승인받은 파일/문자열 목록을 기준으로 별도 복제본에서 git-filter-repo로 제거 결과를 검증한다. 실제 값은 공개 보고서에 기록하지 않는다.
5. 검증 후 별도 승인으로 원격 이력을 교체하고 협업자 복제본도 정리한다. 포크/캐시/PR 참조는 별도 조치 또는 GitHub Support가 필요할 수 있다. 비공개 전환만으로 이미 복제된 자료가 회수되지는 않는다.

기존 민감 문서 내용을 이 보고서나 PR에 복사하지 않았다. 삭제/비공개 전환/이력 재작성은 하지 않았다.
검증된 1단계 코드를 기반으로 2단계 개발은 진행 가능하나, 운영 출시 승인과는 별개다.
