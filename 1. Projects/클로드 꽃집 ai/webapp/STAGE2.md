미완성/3단계 전 보완:
- 실제 AI 배송정보 자동 추출과 이름 혼동 정확도는 미검증. 현재 배송정보는 검수에서 직접 입력 가능.
- 필드별 근거/낮은 확신도 표시 고도화, 검수 초안 임시 저장, 오디오 재생 UI 필요.
- AI 요청이 길면 DB 행 잠금이 지속된다. 비동기 작업과 시간 제한/만료 재처리 보완 필요.
- 같은 내용을 의도적으로 다시 주문하는 운영 절차와 중복 해시 보존 기간 결정 필요.
- 원문·오디오 암호화 보관/삭제 기간과 운영 백업 정책 승인 필요.
- 실제 모델을 호출하지 않은 테스트로 추출 정확도 완료 판정을 내리지 않는다.
모바일 대시보드·인쇄·배송·문자는 다음 범위다. 운영 사용은 아직 불가.
운영 배포, main 병합, 고객 데이터 변경, 공개 저장소 이력 변경은 실행하지 않았다.

## PR #2 미완성 항목 보완 — 2026-11-16

이 구역은 위 최초 초안의 미완성 목록을 갱신한다.

- `code/order_draft_bot.py`: 기존 AI 추출 요청에 배송 날짜·시간·주소·전화 및 필드별 정확한 원문 발췌 계약을 추가했다. 상대 날짜에 기준일이 없으면 추측하지 않는다.
- `webapp/evidence.py`: 명시적 배송 레이블은 원문에서 보완 추출한다. 날짜/시간/주소/전화 후보가 복수이면 자동 선택하지 않는다. 모델의 근거는 실제 원문 부분문자열일 때만 인정하고 근거가 없으면 신뢰도 0으로 표시한다. 점수는 확률 보장이 아닌 검수 우선순위용이다.
- `webapp/app.py`, `database.py`: 모든 검수 항목의 신뢰도·원문 발췌 표시, 빈 필수정보를 포함한 초안 임시 저장·재조회 복원. 초안은 원래 AI 결과를 덮어쓰지 않으며 버전 불일치 시 409로 충돌을 알린다. 승인 전 필수정보 검사와 사람의 원문 대조 확인은 유지한다.
- `analysis_worker.py`, `intake.py`: AI 전체 실행을 Linux 별도 프로세스로 분리했다. 기본 45초(환경변수 AI_REQUEST_TIMEOUT_SECONDS, 최대 120초) 후 종료한다. SDK 요청은 20초 제한, SDK 자동 재시도는 0회다. 접수별 총 시도 3회 한도로 사용자가 재시도한다. 실패 원문은 보존하고 수동 접수는 계속 가능하다.
- `schema.sql`: 처리 번호, 시도 횟수, 150초 작업 유효기간과 주문별 초안 컬럼을 추가했다. AI 실행 중 DB 연결·행 잠금을 유지하지 않는다. 확정 저장 시 처리 번호를 재확인해 이전 작업의 늦은 결과를 폐기한다. 만료된 작업은 재시도로 복구하며 수동 접수는 이전 AI 작업의 저장 권한을 취소한다.

현재 로컬 구현 범위에서 요청한 미완성 항목은 연결했다. 운영 완료와는 별개다.
실제 AI API/음성인식 정확도 및 운영 재배포는 미검증이며 이 PR은 Draft로 유지한다.
Linux fork 작업자 방식은 Windows 개발 서버용이 아니다. 배포 대상 Linux 환경에서 웹 작업자 설정과 요청 제한을 확인해야 한다.
실제 날짜·주소의 실재 확인이나 전화 도달 여부는 자동 검증하지 않는다. 상대 날짜/불명확 정보는 사람이 검수한다.
원문·녹음의 운영 암호화/보관 기간, 의도적인 동일 주문 재접수 정책은 운영 전 결정 사항이다.
3단계·갤럭시 연동은 구현하지 않았다. 운영 DB 변경/배포/병합/고객정보 사용/유료 API 호출도 하지 않았다.
