# 2단계 구현 기록

기준: 1단계 재검토 수정 커밋 6743815. 재검토 상세는 STAGE1_REVIEW.md.
기존 Flask와 code/ 봇 공개 함수를 재사용했다.

변경: intake.py 접수·중복 해시·분석·수동 분리·재시도·문의 추적, schema.sql 접수 원본/오디오 저장,
app.py 새 접수 진입과 개별 필수정보 검수, security.py 새 접수 경로 권한,
tests/test_stage2.py와 기존 접수 테스트 경로 변경.
원문과 녹음은 DB 내부에 저장하며 공개 다운로드 경로는 없다.
같은 텍스트(앞뒤 공백 제외) 또는 동일 바이트 오디오는 이미 존재하는 접수를 반환한다.
내용이 다른 녹음 인코딩/표현만 바뀐 문자는 의미 기반 중복 검사를 하지 않는다.
접수 행 잠금과 주문 생성 트랜잭션으로 같은 접수의 동시 재시도 및 부분 등록을 막는다.
비주문 문의도 기록한다. 실패 시 error 상태로 보존하고 수동 입력/재시도를 제공한다.
수동 주문 분리는 새 줄 --- 구분자를 사용하며 원문을 변경하지 않는다.
검수 시 배송일/시간/주소/연락처, 역할별 이름, 상품, 금액, 리본과 명시적 대조 확인이 필요하다.
검수자가 수정한 금액을 price와 amount_krw에 같은 정수로 저장한다.

검증: 가상 데이터/가상 AI 응답으로 1~3건, 상품/금액 혼합, 역할별 이름,
누락 배송정보, 문자/오디오 중복, 승인 중복, AI 실패/재시도, DB 실패, 부분 분석 실패를 검사했다.
실제 고객정보와 유료 API는 사용하지 않았다. 실제 AI의 정확도를 보증하지 않는다.

미완성/3단계 전 보완:
- 실제 AI 배송정보 자동 추출과 이름 혼동 정확도는 미검증. 현재 배송정보는 검수에서 직접 입력 가능.
- 필드별 근거/낮은 확신도 표시 고도화, 검수 초안 임시 저장, 오디오 재생 UI 필요.
- AI 요청이 길면 DB 행 잠금이 지속된다. 비동기 작업과 시간 제한/만료 재처리 보완 필요.
- 같은 내용을 의도적으로 다시 주문하는 운영 절차와 중복 해시 보존 기간 결정 필요.
- 원문·오디오 암호화 보관/삭제 기간과 운영 백업 정책 승인 필요.
- 실제 모델을 호출하지 않은 테스트로 추출 정확도 완료 판정을 내리지 않는다.
모바일 대시보드·인쇄·배송·문자는 다음 범위다. 운영 사용은 아직 불가.
운영 배포, main 병합, 고객 데이터 변경, 공개 저장소 이력 변경은 실행하지 않았다.
