## 5. 운영 및 정보보호 미해결 사항

- GitHub 저장소는 공개로 확인됨. 기존 문서/과거 이력에 민감한 통화 사례 및 실명이 있을 가능성이 있어 별도 정리 필요. 값 자체를 새 문서나 PR 본문에 재기재하지 말 것.
- 저장소 비공개 전환, 기록 익명화·이력 재작성, 노출 비밀정보 교체는 사용자 승인과 별도 점검 후 수행.
- 원문/오디오의 암호화, 접근 범위, 보관·삭제 기간, 적법한 녹음·AI 처리 고지 검토 필요.
- 운영 DB, 백업, HTTPS, 외부 메시지 발송, 유료 API는 별도 승인 전 금지.

## 6. Work 작업 종료 시 반드시 갱신할 규칙

1. **작업 시작 전** 이 문서와 해당 브랜치의 `STAGE*.md`, 관련 PR을 읽고 최신 상태를 재확인.
2. **작업 종료 전** 이 파일의 최종 갱신일, 단계별 상태, 다음 작업과 위험을 실제 결과에 맞게 수정.
3. 아래 형식으로 **새로운 작업 로그를 맨 위에 추가**하며 이전 기록을 임의로 삭제하지 말 것:
   - 날짜/작업명/브랜치/PR 링크
   - 구현 완료 및 변경 파일
   - 실행한 테스트 명령·통과/실패 수·실행 환경
   - 실제 검증한 항목 vs 구현만 한 항목
   - 남은 오류/제약/승인이 필요한 결정
   - 다음 작업을 시작할 정확한 위치
4. 수정은 작업 중인 기능 브랜치에서만 수행하고 PR에 포함. **main 병합·운영 배포·실데이터 변경 금지**(명시적 별도 승인 필요).
5. 테스트를 실행하지 않았거나 결과를 직접 확인하지 않았다면 '통과'라고 쓰지 말 것.
6. 고객 실명, 전화번호, 주소, 통화 원문, 녹음 내용, API 키, 토큰, 비밀번호, DB URL을 로그·커밋·PR에 기록하지 말 것.
7. 서로 다른 Work 작업/브랜치를 동시에 수정할 때 충돌을 피하고 변경 시점을 명시할 것.
